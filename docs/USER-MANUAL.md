# dsh-bot 用户手册

C09 的 [AstrBot 对齐验收](architecture/ASTRBOT-ALIGNMENT-ACCEPTANCE.md)集中记录六区导航与完整旧入口兼容、当时的 staged profile、离线 Chat 零真实发送和执行 broker 限制。离线 Sandbox 的“发送成功”只表示 capture；现已完成 profile 运行切换：保存当前人格影响后续轮次，其他人格的设置在激活后使用。执行能力需独立 broker ready/授权及宿主安全 preset，当前环境不可执行；macOS probe、egress/preview 状态不代表能力已开放。页面交互仅有 Node shim 证据，真实浏览器仍待验收。

本手册面向「已经能打开 DeepSeek Harness（DSH）Web，想把 QQ 接进来」的用户。
安装细节与全部配置项分别见 [README](../README.md) 与 [CONFIG.md](CONFIG.md)。

模块健康、人工动作、表情包库/发送开关及当前人格闭环的完整证据与限制见 [C08 最终验收](architecture/CLOSED-LOOP-ACCEPTANCE.md)。关闭图片发送仍可管理已获授权的表情包库；健康刷新不会自动重启，动作接纳后需观察 operation 终态。此次仅离线测试，没有浏览器二进制，未做真实 QQ/模型/浏览器验收。

> 本插件只连接**你已经运行并登录好的** OneBot v11 网关（NapCat / SnowLuma / Lagrange.OneBot /
> LLOneBot），不下载、不安装、不启动、不注入任何网关。网关怎么装、怎么登录 QQ 不在本文范围。

## 1. 安装到 DSH

完整安装、下载、升级和回退步骤统一见[安装指南](INSTALLATION.md)，旧版先阅读[迁移说明](MIGRATION.md)。安装后重启目标 profile，打开带 token 的 DSH 页面，检查侧栏 bot 名称入口及 /onebot-qq/api/health。

侧栏入口名称使用当前人格的 `profile.displayName`；为空时依次回退到已连接 QQ 的登录昵称、`dsh-bot`。名称会去控制字符、去首尾空白并限制为 40 个 Unicode 字符。侧栏入口需刷新整个网页后更新；六区页头显示当前目的地名称。「关于」仍显示「关于 dsh-bot」。

## 2. 准备 QQ 网关

各家网关都要做两件事：**登录 QQ**，**开启 OneBot v11 的「WebSocket 服务端」（正向 WS）**，
可选再开「HTTP 服务端」。本插件只需要地址和 token，不需要在网关里填任何回调地址（不是反向 WS）。

### 2.1 NapCat（推荐，已验证 v4.18.x）

1. 安装并登录 NapCat（QQ 已登录、机器人号在线）。
2. 打开 NapCat WebUI（默认 `http://127.0.0.1:6099`，登录 token 见启动日志或 `webui.json`）。
3. 进入「网络配置」：
   - 新建 **WebSocket 服务端**（即正向 WS）：默认端口 `3001`，监听地址建议 `127.0.0.1`，
     建议设置 `token`（随机长串），勾选「保存时启用」。
   - 可选：新建 **HTTP 服务端**：默认端口 `3000`，同样建议 `127.0.0.1` + token。
     HTTP 只用于调用发送等接口；不建也能用（全部走 WS）。
4. 保存并重启/重载 NapCat 网络配置。
5. 记下：`ws://127.0.0.1:3001`、`http://127.0.0.1:3000`、两个 token（若都设置了）。

> 不同 4.x 小版本的 WebUI 文案略有差异，认准「WebSocket 服务端 / 正向 WS」而不是「WebSocket 客户端」。
> 官方文档：<https://napneko.github.io/config/basic>
> 安全警告：不要将未鉴权的 3000/3001/6099 暴露到公网，见 <https://napneko.github.io/other/security>。

### 2.2 SnowLuma（已验证 v2.3.x，本插件只读配置）

1. 自行安装并启动 SnowLuma，登录 QQ。
2. 在 SnowLuma 自己的配置/WebUI 中开启 OneBot 网络，记下端口与 token：
   - 全局：`config/onebot.json`；账号级覆盖：`config/onebot_<uin>.json`（`mode:"snapshot"` 时不叠加全局）；
   - 网络在 `networks.httpServers[]` / `networks.wsServers[]`，字段：`enabled`、`host`、`port`、
     `path`、`accessToken`、`role`（用 `Universal`）；
   - 默认端口通常 `ws 3001` / `http 3000`，token 默认自动生成。
3. 本插件有两种用法：
   - **SnowLuma 地址读取模式**（网关类型选 `snowluma`）：填 SnowLuma 安装目录（含 `index.mjs` 与
     `config/`）即可自动读出地址与 token；也可填账号 UIN 指定读哪个 `onebot_<uin>.json`。
   - **手动地址模式**（网关类型选 `onebot`）：按 2.1 的方式直接填 `ws://127.0.0.1:3001` 与 token。
4. 重要边界：本插件**只读** SnowLuma 的配置文件，**不启动、不注入、不修改** SnowLuma
   （其 EULA 限制自动化部署，见 `THIRD_PARTY_NOTICES.md`）。SnowLuma 的安装、登录、升级由你自己负责。
5. 文档：<https://snowluma.github.io/zh/docs/guide/configuration>、
   <https://snowluma.github.io/zh/docs/guide/connect-bot>

### 2.3 Lagrange.OneBot（v1 分支）

- 走 OneBot v11 正向 WS + HTTP；v1 默认 `ForwardWebSocket 127.0.0.1:8081`、`Http *:8083`。
- `appsettings.json` 的 `Implementations[]` 里开启 `ForwardWebSocket`/`Http`，`AccessToken` 即 token。
- 注意端口与 NapCat/SnowLuma 不同，填地址时改成 `ws://127.0.0.1:8081`、`http://127.0.0.1:8083`。
- 文档：<https://lagrangedev.github.io/Lagrange.Doc/v1/Lagrange.OneBot/Config/>

### 2.4 LLOneBot（v8.x）

- 配置在 `bin/llbot/data/config_<QQ号>.json` 的 `ob11` 段；WebUI 默认 `http://localhost:3080`。
- 默认正向 WS `3001`、HTTP `3000`、`messageFormat:"array"`、`token:""`（**务必自己设 token**）。
- token 走 `Authorization: Bearer <Token>`。
- 文档：<https://luckylillia.com/guide/config>

### 2.5 四家对照

| 网关 | 协议 | 正向 WS 默认端口 | HTTP 默认端口 | 鉴权 | 默认配置位置 |
|---|---|---|---|---|---|
| NapCat v4.18.x | OneBot v11 | 3001 | 3000 | `Authorization: Bearer` 或 `?access_token=` | `config/onebot11_<uin>.json` / WebUI |
| SnowLuma v2.3.x | OneBot v11 | 3001 | 3000 | `Authorization: Bearer` 或 `?access_token=` | `config/onebot.json` + `onebot_<uin>.json` |
| Lagrange.OneBot（v1） | OneBot v11 | 8081 | 8083 | `AccessToken`（Bearer） | `appsettings.json` |
| LLOneBot v8.3.x | OneBot 11 / Milky / Satori | 3001 | 3000 | Bearer | `bin/llbot/data/config_<QQ>.json` |

## 3. 在面板里填地址与 token

侧栏 bot 名称入口 → System → 连接，填写地址与 token；网关类型、机器人 QQ 号与账号核验策略在 System → 常规。

| 字段 | 必填 | 说明 |
|---|---|---|
| 网关类型 | 是 | 「连接已有 OneBot v11 地址」= 只连你填的地址；「从 SnowLuma 安装目录自动读取地址」= 只读 SnowLuma 配置 |
| WebSocket 地址 | 是* | `ws://127.0.0.1:3001`；用于实时收事件。*只填 HTTP 时插件能发消息但收不到事件 |
| HTTP 地址 | 否 | `http://127.0.0.1:3000`；用于调用发送/查询接口；留空则所有调用走 WS |
| WS access token | 否 | 网关 WebSocket 服务端的 token（NapCat/SnowLuma 可能和 HTTP 不同） |
| HTTP access token | 否 | 网关 HTTP 服务端的 token |
| HTTP token 携带方式 | 否 | 默认 `bearer`（`Authorization: Bearer <token>`，NapCat/SnowLuma 标准做法）；`query` = `?access_token=`；`header-token` 非标准、仅特定实现 |
| 机器人 QQ 号 | 建议 | 连上后用 `get_login_info` 核验；留空则只展示登录信息、不拦截 |
| 账号不一致时 | 否 | `off` 不检查 / `warn` 只警告（默认、推荐）/ `enforce` 断开并暂停自动重连 |

操作：

1. 分别在所属页面点「保存设置」。System 配置会写入数据目录并**热应用**：端点/账号类改动自动重连。
2. 点「连接」。也可以用「探测」按钮先只走 HTTP 试一次 `get_login_info`，不改连接状态。
3. 「概览」应显示：状态 `已连接`、登录账号（QQ 号 + 昵称）、账号核验 `通过`。
4. 状态不对时先看 Data & Logs → 日志，再对照第 5 节排查。

只配 WS 或只配 HTTP 的行为：

| 配置 | 状态 | 能力 |
|---|---|---|
| 只配 WS | connected | 收事件 + 调接口（走 WS echo） |
| 只配 HTTP | disconnected（`lastError` 会说明收不到事件） | 能调接口/发消息，但**收不到实时事件**；不做轮询 |
| 都没配 | unconfigured | 需要先填地址 |

SnowLuma 读取模式：网关类型选 `snowluma`，填安装目录（也可点「检测」自动探测）→ 插件只读
`config/onebot*.json` 里的 `networks.*` 取地址与 token；读不到会回退到你手填的地址并在日志里说明原因。
注意 SnowLuma 的 EULA 限制自动化部署，本插件不会启动/注入它。

### 3.1 访问控制（建议上线前开启）

默认 `open`：任何私聊/群都能触发回复，保持升级前的行为。真正把 bot 放进群之前，建议在「System → 访问控制」
切换成 `allowlist`。

| 模式 | 谁能触发回复/主动行为 | 被拒绝的消息 |
|---|---|---|
| `open`（默认） | 任何私聊、任何群 | — |
| `allowlist` | 主人私聊、私聊白名单、群白名单 | 不落 raw、不聚合、不回复；只记审计元数据 |

操作：

1. 「System → 访问控制」把模式改成 `allowlist`；
2. 填「主人 QQ」（必填，否则没有主人特权，只有白名单生效）；
3. 在「私聊白名单」/「群白名单」里逐个输入 QQ 号/群号后回车；
4. 保存。概览页的「访问控制」卡片会显示模式、名单数量与最近拦截计数。

说明：

- **群聊按群放行**，不按发言人：群里任何人都能触发（是否回复仍由点名/概率/冷却决定）；不想让某个群触发，就不要把它放进白名单。
- **私聊按人放行**：主人和私聊白名单可以触发，其他人不行。
- 被拒绝的消息**不写入原始事件、不进认知、不回复**；审计只保留会话/发送者/原因/时间，不存消息正文，重启清空。
- 面板「消息」页手动发送是人工操作，不受访问闸门限制。
- 排查某条会话为什么被拒：面板概览计数，或 `POST /onebot-qq/api/access/check`（body：`chatType` / `chatId` / `senderId`）。

### 3.2 会话运行时（实验，默认关闭）

「配置 → 会话运行时 → 引擎」有两个选择：

| 引擎 | 行为 | 适用 |
|---|---|---|
| `oneshot`（默认） | 认知 pipeline 拼 prompt，一次性调用 LLM 生成回复 | 现有部署；无需宿主提供会话服务 |
| `agent` | 每个 QQ 聊天一个 DSH Session，由 Agent 生成回复，可用 preset 里的工具 | 想用工具/长上下文/DSH 原生能力时 |

`agent` 需要当前 DSH profile 提供 `sessionController`、`workspaceRegistry`、`agents`；缺任何一个或调用失败时，
本条消息自动回退到 `oneshot`，不会静默丢回复。

两个 preset 由插件 bundle 声明：

- `dsh-bot-private`：主人私聊，带 `tool-fs` / `tool-fs-search` / `tool-web`，人格与规则来自 `{{dshbot_persona}}` / `{{dshbot_rules_private}}`；
- `dsh-bot-social`：群聊与他人私聊，只有人格与时间上下文，不挂本机工具。

此外，运行时只给主人私聊（`level=full`）挂 3 个当前会话 QQ 工具：额外发送文本、给当前私聊对象点赞/戳一戳。social/group session 不注册这些工具；群信息/成员信息通过 `/groupinfo` `/memberinfo` 命令使用。额外文本仍经过访问控制和限频。工具不能指定其它聊天，也不提供资料编辑、群管理、精华、撤回、文件工具或通用 action bus。

**Agent 沙盒工具（C07，默认关闭）**：仅 sandbox enabled、broker ready 且当前会话策略许可时挂载 `sandbox_file_list`、`sandbox_file_read`、`sandbox_file_write`、`sandbox_shell`、`sandbox_python`、`sandbox_action`。参数仅作业输入/工作区相对路径；不能指定角色、宿主路径、环境或网络。当前没有 Python，调用返回固定不可用；action 仅删除工作区文件。默认仅主人私聊许可，操作员/他人/群聊拒绝；输出最多 16 KiB，完整 broker artifact 最多 64 KiB。一次性模型回复中的 JSON/代码只是文本，不触发执行。

沙盒启用后必须另行提供 `dsh-bot-sandbox-private` / `dsh-bot-sandbox-social` 安全 preset，排除通用 fs/fs-search/web/shell 工具。当前受保护 bundle patch 未修改，**这两个 preset 尚未配置**；缺失时 Agent 安全失败、回退 oneshot 文本，不回退 legacy 本机工具。broker unavailable/disabled 时不挂 sandbox 工具，当前宿主尚无可用执行驱动。默认 sandbox 关闭时沿用上述 legacy preset/QQ 行为；进入沙盒模式后本 runtime 不降级 legacy preset。具体 preset 内容与限制见 [ADR-022](architecture/ADR-022-agent-execution-broker.md#c07-preset-缺口不改-live-patch)。

会话同时绑定人格/策略代次、发送者、聊天、preset 与 runtime/session 实例；切换或编辑人格、撤权、卸载均撤销旧工具引用、取消作业并更换会话，跨重启不恢复旧绑定。已接纳的 QQ 发送/文件原子写入不能回滚。

会话映射写在数据目录 `runtime/sessions.json`，工作区默认在 `runtime/workspace`；单轮等待上限由
「会话运行时 → 单轮回复超时」控制（默认 120s，超时撤销工具、取消沙盒作业并退休会话，尝试停止 Agent；迟到事件被忽略）。概览「运行诊断」会显示
`运行时：agent/oneshot` 与当前会话数；也可看 `GET /onebot-qq/api/runtime/stats`、`/runtime/sessions`。

建议先在测试号打开 `agent`，确认回复、工具调用与回退都正常，再考虑默认开启。`agent` 仍是实验路径：真实 QQ 工具调用尚未完成真机验证；按聊天模型只影响认知 LLM，不改变 Agent Session 模型。

**主人插话（M7-o）**：在当前主人私聊或群聊发送 `/steer 先说结论`，把文本交给当前 DSH Session 的 `agent.steer`；没有映射时按现有 private/social preset 创建 Session。文本须为 1–1000 Unicode 字符（空白文本无效），命令前后空白会去除。只在 agent 运行时且宿主支持 steer 时可用；oneshot/服务缺失回复「当前不是 agent 运行时，无法插话」，宿主缺少方法会明确提示不支持。成功提示只表示已交给 Session，不保证当前回合已完成。`runtime.stats.steers` 统计成功次数。

仅主人显式命令触发，非主人在私聊/群聊均静默；不会把普通群成员消息自动升级为 steer。命令受访问控制与命令禁用列表约束，不写配置、不直接调用模型，没有插话面板/API。M7-q 另有默认关闭的私聊输入状态开关，见下文；steer 仅 fake agent 离线测试，真实 DSH/QQ 未验证，GAP #9 仍为 partial。

### 3.3 按聊天选模型与 QQ 命令（主人/只读操作员）

**按聊天选模型**（「配置 → 模型路由与预算」）：

- `私聊默认模型` / `群聊默认模型`：填 `provider/model`，留空用全局路由；
- `按会话覆盖`：每行 `QQ号或群号=provider/model`，优先于默认项；
- 也可在 QQ 里用 `/model provider/model` 给当前会话设置，`/model clear` 清除。

只影响认知分析与回复生成，不改变 DSH 面板的默认模型；`agent` 引擎的 Session 模型仍由 DSH preset 决定。

**今日 LLM 预算**：打开「System → 模型」，卡片同时显示全局与当前人格的今日已用、预算、剩余、进度和 UTC 日期，并显示当前模式的有效剩余。「Profiles → 模型」中的「预算作用域」可选全局（`global`，默认）、按人格（`persona`）或两者取最小（`both`）；全局与人格预算默认均为 300000，可分别编辑。两项计数始终记录，切换模式不会清零。分析与回复计入两项用量，学习预算在 `cog-learning` 单独配置。达到 80% 提示；参与约束的预算耗尽后阻止后续模型调用，仅跟踪的预算耗尽不会阻止。服务层预算 0 也视为耗尽。

点「刷新」更新数据，读取失败时可「重试」。「重置全局今日」清除所有人格共享的全局今日计数；「重置当前人格今日」只清除当前人格的今日计数，两者均弹出确认，取消不发请求。不会修改预算、模式、人格或配置，其他日期保留。人格重置不影响其他人格；全局重置不清除各人格计数。加载、错误、重置中或对应行用量为 0 时重置按钮不可用。重置不撤销供应商用量，执行中的调用仍可随后增加计数，归属请求开始时的人格。旧全局计数保留在全局存储，不再迁到人格；人格计数从新增双计数后开始记录。若已运行中间迁移实现，不自动合并其历史人格记录。详见[配置说明](CONFIG.md#llm-每日预算与今日用量)。

**QQ 命令**（主人全量；只读操作员固定集；其他用户静默，公开模块命令例外；回复仍受访问控制/频率限制）：

**只读操作员（M7-r）**：在「System → 访问控制 → 只读操作员 QQ」添加 QQ 号（`access.operators`，默认 `[]`，按私聊列表规则去空白/去重，最多 500 项）。allowlist 自动放行其私聊入站与出站，原因 `operator`；群聊仍须群白名单。主人身份优先，不因同时列入操作员而失去权限。

### QQ 管理审批（M7-s）

`cognition.qqAdmin.requireApproval` 默认 `false`，管理动作继续按原方式执行。需要逐次审批时，在「配置 → QQ 管理命令」打开「QQ 管理动作需要主人审批」。随后发送 `/kick 10002 confirm` 等管理命令只产生 `apr_` 待办，不执行动作；原踢人/撤回确认要求保留，点赞/查询等非管理命令不变。

主人发送 `/approvals` 查看待办，再完整复制 ID：`/approve apr_列表中的完整ID confirm` 批准并在原聊天执行，或 `/reject apr_列表中的完整ID confirm` 拒绝。列表按最新排序最多 10 条，参数脱敏为单行；每项 10 分钟有效，最多同时 50 条。队列跨重启和人格切换保留。审批命令仅主人可用，其他人静默；`req_` 好友/群请求仍按原规则处理。

批准会重新核对原聊天访问、当前主人/开关/禁用列表及参数，结果发回原聊天。每个 ID 只处理一次；过期、未知或已处理不能重用。失败/超时或批准后进程中断不会自动重试，先核实 QQ 实际状态，再决定是否重新发起。已知密钥模式和控制字符不能进入审批参数，超过 300 字符也拒绝；不保存额外原事件字段。没有审批面板/HTTP、全服务/工具统一审批或 PII/媒体内容扫描；#15/#14 仍 partial，仅 fake QQ 离线验证。详见[配置](CONFIG.md#qq-管理审批m7-s)。

命令在轮次聚合的快速路径上处理，不进入分析/策略；主人 `/quiet`、`/active`、带设置/清除参数的 `/model` 会写回配置并立即生效；操作员 `/model` 只读。

**通知与请求（M7-j）**：默认启用 `cognition.notices.enabled`、`cognition.requests.enabled`，在配置页可关闭。已接受的进退群、管理员、禁言、名片、群名、头衔、精华、好友添加和离线文件通知会出现在当前人格时间轴「事件」中；不下载文件、不自动回应。原撤回/拍一拍/表态仍走原管线，未知事件忽略；暂停/拒收时不新增记录。

好友申请、加群申请/邀请只进入当前人格待办，不自动批准或拒绝。用 `/requests` 查阅，再发送 `/approve req_列表中的完整ID confirm` 或 `/reject req_列表中的完整ID confirm`（把占位文本替换为实际 ID）。仅主人可操作，动作和回复受当前聊天访问控制；建议在主人私聊查看含 QQ 号/备注的列表。列表最多 10 条，处理后可继续查询；请求 ID 按 flag 去重，已处理的不能再次操作。成功才记录批准/拒绝；失败保持 pending，回复不包含网关原始错误、flag 或原始备注。网关超时后先核实实际处理状态再重试。确认要求不受 `cognition.qqAdmin.requireConfirm` 影响。

备注会去控制字符、脱敏已知密钥和 flag，保存最多 500 Unicode 字符，命令仅显示最多 100 字符摘要；flag 只留在本地存储供网关使用。QQ 号/备注仍是隐私数据，没有 PII 检测。人格数据「请求」组可统计/复制/删除，复制待办不会触发审批；真实 QQ 请求在不同人格副本中仍是同一请求。没有审批面板或新增审批 API/Agent 工具；仅 fake 网关测试，真实 QQ 未验证。配置与边界见 [QQ 通知与请求](CONFIG.md#qq-通知与请求m7-j)。

#### 手动跨平台身份登记（M7-v）

仅主人可以维护默认空的全局手动链接；操作员和陌生人在私聊/群聊均静默。命令先检查身份、禁用列表和当前聊天出站访问，列表回复到当前聊天。

| 命令 | 作用 |
|---|---|
| `/identity` | 按创建时间从新到旧列出最多 20 条，格式 `platform:externalId → personId · label`，无标签时省略标签 |
| `/identity link platform externalId personId [label]` | 登记或重链；相同平台/外部 ID 只有一条，重链保留 ID/创建时间，更新 personId/更新时间；省略标签保留旧标签 |
| `/identity unlink platform externalId` | 删除对应手动链接；不存在时提示未找到 |

例如 `/identity link telegram alice person_alice Alice 的登记账号`，再用 `/identity` 查看；`/identity unlink telegram alice` 移除。平台严格限 `qq`、`telegram`、`discord`、`matrix`、`custom`，这里只是标识，不会启用 adapter。externalId 为 1–64 字符、匹配 `^[A-Za-z0-9_.:@-]+$`；personId 为 1–80 字符、匹配 `^[A-Za-z0-9_-]+$`。大小写精确匹配，不自动归一/推测；可填现有人物 ID 或人工引用，服务不检查或创建人物。标签可选，最多 80 Unicode 字符，去首尾空白，拒绝控制/方向格式字符与已知密钥模式；ID 也拒绝已知密钥。请勿登记凭据，规则不等于通用秘密检测。

全局最多 5000 条；满后仍可重链/删除。服务另有 resolve、平台/personId 筛选、最新最多 100 条与 counts；没有 HTTP/API 或面板入口。记录为 `source=manual`、随机 `idn_` 加 24 hex，独立持久化到全局 `manual_identity`，跨重启/人格切换保留，不随人格复制或删除。它与既有人物 identity 分开，不创建/修改/合并人物、不自动验证账号所有权或合并身份、不改变 QQ 人物解析或消息路由。无 Telegram/Discord/Matrix adapter、网络调用、新配置或依赖；默认空、未使用命令时消息行为不变。仅离线存储/fake QQ 测试，真实跨平台未验证，#32 从 none 改为 partial（手动登记基础）；6 has / 40 partial / 0 none / 1 limited / 6 leading / 8 exempt，remaining 47，#31/#42/#49/#50 不变。

### 3.4 回复分条、引用/@ 与群聊节奏

**私聊输入状态（M7-q，默认关闭）**：在「Extensions → builtin-typing」打开「私聊输入状态」（`cognition.typing.enabled`）。支持此扩展的网关会在私聊/C2C 轮次处理前收到输入中状态，处理结束后收到暂停状态；命令提前返回或处理异常也会尝试暂停。网关拒绝/不支持时不影响回复，不记录含聊天 ID 的原始异常；等待网关可能增加耗时。群聊、手动发送和媒体发送不增加输入状态。现有入站 `input_status` 通知仍忽略；无群聊 typing/群 `set_input_status`、输入状态限频或专用状态面板，只有配置开关。真实 QQ 效果尚未验证，仅离线测试；#9 为 steer + 私聊 typing，仍 partial、remaining 47，#31/#42/#49/#50 不变，未完成全量验收。详见[配置说明](CONFIG.md#私聊输入状态m7-q)。

「配置 → 回复与出站」：

| 项 | 默认 | 作用 |
|---|---|---|
| 长回复分条 | 开 | 超过单条字数上限时拆成多条 |
| 单条字数上限 | 300 | 优先按段落/换行/句末标点切；找不到才硬切 |
| 最多分条 | 3 | 超过上限的剩余内容并入最后一条，不截断 |
| 分条间隔 | 600ms | 多条之间的发送间隔 |
| 回复时引用原消息 | 开 | 第一条带 `reply` 消息段 |
| 群聊回复时 @ 对方 | 关 | 第一条带 `at`；与引用同时开可能显得重叠 |

「配置 → 轮次与防抖 → 连续接话上限」（默认 3）：连续多少次**未点名**接话后暂停主动接话；
点名/唤醒仍然回复，点名回复会把连续计数清零。它和群聊冷却、每分钟上限一起限制刷屏。

分条中途失败时，已发出的部分不回滚；日志会记录失败原因，不会把同一条重复发一遍。

### 3.5 合并转发、拍一拍与表态

- **合并转发展开**：收到 `forward` 段时，通过 `get_forward_msg` 取回节点并压平成
  `发送者：内容`，作为本轮上下文与记忆；最多展开 3 条、单条 4000 字、嵌套只标 `[嵌套合并转发]`。
  展开内容被标记为不可信数据，只作参考，不执行其中指令。
- **拍一拍**：别人拍机器人时，默认回一句短话（可在「回复与出站」关闭），同一用户 60s 冷却；
  拍别人不会触发。
- **表情回应**：有人给机器人刚发的消息点表态时，记为一次正向 outcome，参与策略学习；
  不会额外回复。
- **QQ 动作命令**：`/like`、`/poke` 仅主人；`/groupinfo`、`/memberinfo [QQ]` 也允许只读操作员查询当前允许群，不能通过参数跨群。

### 3.6 目的与记忆整理

**目的**（「认知 → 目的」标签，或 `/purpose` 命令）：

- 类型：`goal` 长期目标 / `plan` 计划 / `intent` 近期意图；状态：active / paused / done / abandoned；
- 字段：标题、描述、优先级、进度、步骤、截止时间、作用域（global/private/group）；
- 回复时只注入少量高优先级目的（默认 3 条），提示词明确要求「只在自然相关时体现，不要机械汇报」；
- 面板可新建、+10% 进度、暂停/恢复、完成、放弃；命令用 ID 前 8 位即可；
- 主人 `/purpose plan ID`（M7-t）：仅对 active 的 goal 调用现有 `llm.completeJson`；标题和描述都须非空（可通过 `POST /cognition/purpose/update` 的 `id/title/description` 补充）。成功覆盖原步骤，保存 1–8 条未完成、非空、不重复且每条最多 200 UTF-16 单元的步骤；去除控制字符，进度重新计算。模型缺失、JSON/步骤无效或目标在生成期间变化时不写入，错误不回显模型或服务细节。
- 主人 `/purpose step ID N [done|undo]`：N 为 1–20 且必须存在，默认 done；只修改该步骤的完成标记并回复进度。`/purpose steps ID` 最多列 20 条及进度；支持完整 ID 或唯一短前缀，歧义拒绝。已有服务在 active 目标全部完成时置为 done；undo 降低进度但不自动恢复状态，需要时另用 `/purpose resume ID`。
- 目的本身**不执行工具**，也不自动发消息；M7-t 只保存计划/手动标记并回复当前聊天，不执行步骤、不绑定动作或接入审批。未使用 plan 时没有新增 LLM 调用或后台执行；无新配置，默认行为不变，GAP #38 仍 partial。

**记忆检索（M7-f）**：默认使用本地词法/FTS 与关联图，无 embedding 网络请求。可在「认知 → 设置 → 记忆」打开 `cognition.memory.embedding.enabled`，填写 Base URL、模型及密钥环境变量名，默认权重 0.35。开启后会向所配 OpenAI 兼容 `/embeddings` 服务发送查询与候选记忆文本；仅重排词法候选，不做全库向量召回。provider 出错、超时或响应不合法会回退词法检索；空查询/无候选不调用。同步面板查询保持词法检索。配置与批次/维度/缓存限制见 [CONFIG](CONFIG.md#可选语义检索cognitionmemoryembeddingm7-f)。无本地模型、独立 reranker 或向量数据库；目前仅 fake provider 离线测试通过，真实 provider 未验证，#31 仍部分实现。

**每日整理**（「认知 → 记忆 → 整理/反思」按钮，或 `POST /cognition/consolidation/run`）：

- 默认每天 04:00 扫描情景记忆，按作用域巩固为语义记忆；
- 可选 LLM 阶段反思：只压缩已有记忆、不新增事实；按作用域隔离（私聊不跨聊、不写 global）；
- 同一作用域低于「反思最低条数」不调用 LLM；预算不足/失败直接跳过；
- 配置项在「记忆」页：每日整理开关、时间、LLM 反思、反思最低条数。

**时间轴**（「认知 → 时间轴」）：轮次/记忆/决策/导入事件按时间合并，可按类型和 scope 过滤，只读；不是可编辑的回忆库。

**导入旧档案（M7-d/M7-h）**：在「认知 → 记忆」列表下方打开「导入旧档案」，先选择「记忆」（默认）或「时间轴」，再选择 `.json/.jsonl/.txt` 文件（内容必须是 JSON/JSONL），选择全局、当前人格私聊或群。私聊/群须输入纯数字 QQ 号/群号，默认全局；各项自带的 scopeType/scopeId 可覆盖面板选择。点击「导入」后显示导入种类及 imported（导入）/skipped（跳过）/invalid（无效）/bytes（字节）并刷新当前搜索。

- 内容存入**导入时当前人格**，全局仅表示该人格内全局可见；可先切换到目标人格。
- 默认最多 5 MiB、5000 项，可通过 `cognition.import` 调低或禁用。大小/条数超限整批拒绝，不会先写一部分。
- 记忆 JSON 支持数组、含 `memories/items/data/records` 数组的对象，或单个记忆对象；JSONL 每个非空行一个对象。JSON 解析失败整批报错；JSONL 坏行/无效项计入 invalid；没有有效项时报错。
- 记忆正文用 `text/content/summary/memory`，每项 1–4000 Unicode 字符。可提供 type、personId、importance、createdAt/updatedAt；详细字段规则见 [CONFIG](CONFIG.md#导入旧档案cognitionimportm7-d)。
- 记忆按相同作用域、personId、正文生成相同 ID，重复项跳过；重导不会覆盖已有记忆或重新激活已遗忘记忆。服务本地处理，不上传到外部服务、不调用模型、不自动发送 QQ；导入后的记忆会参与日常检索与配置的整理流程。

- 时间轴 JSON 支持数组、`events/timeline/items/data/records` 数组包装或单项（包括 `kind:"timeline"`），也支持 JSONL。正文用 `text/detail/summary/content/title`，限 1–2000 Unicode 字符；可选标题 1–200 字符。必须提供 `at/timestamp/time/createdAt`（毫秒数或 ISO），缺失项无效，无效/未来值回退为本次导入时间。按作用域/personId/时间/正文去重，独立于记忆；无效时间跨时刻重导可能不去重，建议先修正原时间。导入后到「认知 → 时间轴」查看，默认全部包含事件，可点击「事件」单独筛选；事件不参与记忆检索/整理。

以下为**合成格式示例**，不是真实旧档案样本：

```json
{"memories":[{"text":"喜欢喝不加糖的茶","type":"semantic","scopeType":"private","scopeId":"12345","importance":0.8,"createdAt":"2025-01-01T00:00:00Z"}]}
```

同一内容也可逐行保存为 JSONL；API 为 `POST /onebot-qq/api/cognition/import`，请求体例子：

```json
{"format":"auto","content":"[{\"text\":\"合成旧记忆\"}]","scopeType":"global","scopeId":""}
```

时间轴档案示例（合成数据）：

```json
{"events":[{"title":"初次相识","detail":"一起聊过茶","at":"2025-01-01T00:00:00Z","scopeType":"private","scopeId":"12345"}]}
```

API 时间轴请求示例：

```json
{"kind":"timeline","format":"auto","content":"[{\"text\":\"合成回忆事件\",\"at\":\"2025-01-01T00:00:00Z\"}]","scopeType":"global","scopeId":""}
```

**仍未做**：Aurabot 专用档案迁移、人物/群档案完整编辑页、向量导入；没有真实旧档案样本验证，GAP #30 仍为部分实现。

### 3.7 媒体与表情包（M4-a/M4-b/M7-c）

媒体默认完全关闭。在「System → 媒体」先开 `media.enabled`，再按需开启图片、Vision、生图、改图、ASR、TTS 或文件。Provider 使用 OpenAI 兼容接口；配置里只填 API Key 的环境变量名，密钥本身放在启动 DSH 的进程环境中。

- 图片：下载入站图片；可选 Vision 会把一句 `[图片：描述]` 追加到本轮上下文。底层 `sendMedia` 使用 `base64://`；普通图片没有独立发送控件，表情包走 `/sticker`，见下。
- 语音：开启 ASR 后下载 record 并转写，追加 `[语音转写：…]`；TTS 只生成 `<数据目录>/media/outbound/*.mp3`，不会自动发到 QQ。
- 文件：下载允许扩展名的文件；底层支持 OneBot `upload_group_file` / `upload_private_file`，但没有任意路径上传 API。
- 所有媒体受 `media.maxBytes`（默认 10 MiB）和扩展名白名单限制；失败只在 debug 日志记录，不会让普通消息处理失败。
- 顶层「媒体」页显示媒体、Vision、生图、改图、ASR、TTS 与表情包状态。TTS 测试只在本机生成 MP3 并显示文件位置，不会发送到 QQ。
- 表情包支持 PNG/JPG/JPEG/GIF/WebP，默认单图 5 MiB、最多 200 个。通过媒体页上传、预览、编辑逗号分隔标签或删除；相同内容按 SHA-256 去重。
- 主人可在当前聊天使用 `/tts 文本` 合成并发送语音（默认最多 300 字符）、`/say 文本` 发送一次文本、`/sticker [标签]` 从匹配项随机发图。三者均受主人身份、白名单和当前聊天出站权限约束。
- 诊断接口：`GET /onebot-qq/api/media/status`；`POST /onebot-qq/api/media/test` 只接受 `tts`、`asr`、`vision` 并使用内置样本；`POST /onebot-qq/api/media/tts` 只接受文本并返回本地生成文件路径。

媒体页「文件」（M7-k）提供本地上传、列表和刷新。先开启 `media.enabled` 和 `media.files.enabled`，再选择 `txt/md/json/csv/pdf/doc/docx/xls/xlsx/ppt/pptx/zip/7z/rar` 文件；文件不能为空且不能超过 `media.maxBytes`（默认 10 MiB）。名称限 120 字符的安全文件名，不接受目录。接口 JSON 请求体上限为 15 MiB，含 base64 展开；调高媒体上限不会调高接口上限。

上传保存在媒体根的 `files/` 中，以时间戳/随机前缀避免覆盖。列表显示文件名、相对路径、大小和修改时间，最新优先最多 500 项，合计字节数包含所有合格文件；不显示子目录、符号链接、不允许的扩展名或超限文件。功能关闭时显示「文件功能未启用」，不影响其他媒体区。复制完整相对路径，用主人命令 `/file files/<上传后的文件名>` 发送到当前会话；命令还需 `cognition.qqAdmin.enabled` 和访问许可。文件区没有发送、删除或下载按钮；不会自动发送 QQ，真实 QQ 文件收发仍未验证。

生图/改图默认关闭。在配置里开启 `media.enabled` 与 `media.images.generateEnabled` / `editEnabled`，填写 Base URL、模型和密钥环境变量名；改图的地址/模型/环境变量名留空会沿用生图配置。默认生图模型是 `gpt-image-1`，实际模型/字段兼容性由 provider 决定。媒体页「生图/改图」输入 1–1000 字符提示词、选择尺寸（256×256、512×512、1024×1024、1792×1024、1024×1792），改图另输入源图片相对路径，再点「生成图片」或「编辑图片」。页面显示返回路径或错误，只落盘，不发送 QQ；不提供本地路径选择器或新的图片上传/下载入口。

主人发送示例：`/draw 一只猫`、`/redraw generated/示例.png 改为蓝色背景`、`/image generated/示例.png`。这些命令还需开启 `media.images.enabled`，先通过当前会话 `access.canSend`，成功只发送一张图片，没有额外确认文本；`/image` 不要求开启生图/改图，也不要求 QQ 管理命令开关。路径相对于媒体根，拒绝绝对路径、Windows 路径、控制字符、`..`、目录及符号链接逃逸；允许 jpg/jpeg/png/gif/webp/bmp，大小受 `media.maxBytes` 限制。

本地接口 `POST /onebot-qq/api/media/image/generate` 接受 `{prompt,size?}`，`POST /onebot-qq/api/media/image/edit` 接受 `{path,prompt,size?}`，返回 `{ok:true,path,size}` 或 `{ok:false,message}`。结果只接受 provider 的 PNG `b64_json`，不抓取返回 URL，不跟随重定向；保存为 `generated/<uuid>.png`。PNG 头尺寸每边最多 1792、总像素最多 1792×1024；源/输出大小沿用媒体上限，超时沿用 `timeouts.callMs`（媒体限制 1–120 秒）。改图只调用 OpenAI 兼容 edits，没有 mask、转码或其他编辑后端；真实 provider 和 QQ 生图/改图未验证。

当前不会自动收集聊天图片、按语境挑表情、缩放转码或连接表情包商城；也不包含 Agent 媒体工具、RVC/翻唱、自动语音策略、兼容 edits 之外的图片编辑或任意本地脚本接口。真实 OneBot/provider 兼容性需在自己的测试号上验证。

### 3.8 B站公共内容与 QQ空间边界（M5-b / M7-m）

在「模块 → 媒体功能」详情启用模块并打开 `content.bilibili.enabled` 后，主人与只读操作员可以使用 `/bili hot`、`/bili 关键词`、`/bili BV号`、`/bili comments BV号`、`/bili share BV号`。模块详情的操作面板提供搜索/热门，原「内容」页保留入口指引。详情还提供 BV 输入框、公开评论查询与分享链接显示。BV 号须为 BV 加 10 位字母或数字，不接受整条 URL。

REST 路由统一以 `/onebot-qq/api` 为前缀：`GET /content/bilibili?q=`、`GET /content/bilibili/hot`、`GET /content/bilibili/comments?bvid=&limit=`、`GET /content/bilibili/share?bvid=`。评论 limit 默认 10，取整后限制为 1–20；置顶在前、按 rpid 去重、保留 API 顺序，正文去标签/控制字符、最多 500 Unicode 字符。只读取第一页和接口自带的一层楼中楼样本，无缓存或翻页。

搜索/热门默认最多 5 条，每次公开接口请求默认超时 15 秒；评论先查询详情取得 aid，再读公开评论。分享只离线生成固定域名视频链接，不查询标题、不验证视频是否存在。服务不使用 Cookie、不做 WBI 签名，不提供字幕、登录态或发布评论；被风控或要求登录时会显示明确错误，不会伪造评论或结果。默认关闭，所有入口（包括分享）受开关控制，默认配置零网络；真实 B站接口未验证。

QQ空间明确未实现：它需要 QQ 登录授权，并涉及平台授权与服务条款边界。真实 B站公开接口与 QQ Agent 工具兼容性仍待受控验证。

### 本地主人提醒（M7-l）

先设置 `access.ownerQQ` 并开启 `cognition.reminders.enabled`（默认 false）。仅主人操作当前聊天；群聊须允许统一出站访问，私聊/群 ID 须为正安全整数。

```text
/remind 3600 喝水
/remind 2099-01-01T09:00:00+08:00 新年提醒
/reminders
/forgetreminder rem_返回的完整ID
```

整数秒表示重复提醒（默认范围 60–2592000 秒），未来 ISO 时间表示一次提醒，建议明确带时区。文本 1–500 个 Unicode 字符；回复会显示完整 ID 与下次 UTC 时间。`/reminders` 只列当前聊天最多 10 条活跃记录；取消须使用原聊天的完整 ID。相同作用域/文本/时间不重复创建，每人格默认最多 50 条活跃记录。格式不正确会返回用法或范围错误。

提醒只发送保存的固定文本，受访问控制、频率上限、防泄漏与 dry-run 约束；不调用模型或执行文本里的指令。默认每 30 秒检查一次，每次最多 20 条，重复提醒不会补发错过的多次，失败至少 60 秒后重试。进程停止期间不发送，重启后继续处理到期活跃提醒；发送超时或进程崩溃可能导致重复，不能保证精确到时或 exactly-once。dry-run 会消费一次提醒/推进重复时间。

提醒随人格隔离，切换人格暂停旧人格的后续检查；切回后处理过期活跃记录。人格页「提醒」数据组可统计/复制/删除；复制保留 active 状态，激活副本人格后也可能发送，请取消不需要的副本。关闭功能停止发送但保留记录，重新开启后可列出/取消。没有提醒管理面板/API、DSH jobs、长任务或 LLM 任务执行；真实定时器与 QQ 尚未验证，#8/#40 只达到 partial。

## 4. 面板六区导航

面板使用六个 area；DSH 侧栏仍只有一个 bot 入口，整页面板仍只有一个 main 注册。

顶部 `.ob-commandbar` 包含品牌「小葵」（沿用当前注入名称）、状态圆点、版本、六区入口、搜索与刷新图标；下方 `.ob-sectionbar` 只显示当前区域可见分区。两行随插件滚动区吸附顶部，桌面区域与分区过长时各自横向滚动，正文填满 DSH 分配的面板宽度。插件内部不再提供侧栏、折叠图标轨道或导航偏好。

宽度不超过 900px 时，首行使用「区域」原生选择框及完整简短中文选项，保留品牌、状态、搜索和刷新，隐藏版本文字；首行高 56px 加顶部安全区。第二行改为「分区」原生选择框，高 44px，只有一个分区时隐藏。模块详情显示当前「模块详情」，可从分区选择框或「← 模块目录」面包屑返回列表。触控目标至少 44px；没有抽屉或 hamburger。移动输入/select 至少 16px，保留安全区和底部显式保存栏。

点击搜索或按 Ctrl/Cmd+K 打开命令搜索面板；输入页面、旧名称或设置路径，用 ↑↓ 选择、Enter 跳转、Escape 关闭。Tab/Shift+Tab 在输入和关闭按钮间循环；关闭按钮或遮罩也可关闭并恢复原焦点。搜索结果沿用 `goTo`，不新增后端。页面加载或报错时命令栏仍可使用。

UI rework phase A 替换了旧导航，phase B 将模块目录与详情改为管理卡片、健康结论和折叠技术信息，phase C 收紧移动命令栏与详情头部，沿用既有显式保存机制。[响应式验收契约与浏览器矩阵](design/responsive-navigation-modules.md)列出自动化证据及待验收项。DSH 的新版真实 Chromium 已确认桌面全宽顶部壳层与模块列表改善；phase C 根据 390px 区域裁切、详情控件占高及路由误标继续修正。自动化覆盖交互和 CSS 契约；phase C 各尺寸、DSH 外层侧栏、主题、缩放、软键盘及读屏体验仍待 DSH 捕获新截图验证。

搜索只索引页面标签、旧名称和配置路径，不索引当前值、默认值或密钥。选择设置路径会直接进入唯一所有者位置，混合旧组不会生成第二份编辑器。旧 15 标签、15 认知分区、31 配置组（含新增 sandbox）、五个外观分类、模块 ID、字段与 `ob-media-*` / `ob-cog-*` / 模块锚点继续直接解析。`config` 落在 System 常规；`cognition` 落在 Profiles 概览；未知目标回到 Overview。

页头只显示区域、紧凑标题与单行说明；全局状态/版本/刷新集中在命令栏。切换区域、分区、模块详情及前进/后退时，插件滚动区回到页首并聚焦新标题；数据刷新保持当前位置。设置路径和显式功能/配置锚点仍定位到对应内容，并为吸附命令栏留出空间。

内部目的地写入 URL 的 `ob-nav` 参数；保留 DSH 外层 path/hash、其它 query 和 history state。支持刷新恢复、后退/前进与同区更新；moduleId、anchor、decisionId、taskId 保持完整 ID。旧 `#ob-tab-*` 链接在没有 `ob-nav` 时也会解析。

**Profile 设置已应用于运行。** 在所有者设置选择「设置人格」后，读取/保存指定 ID，检查或保存其他人格不会激活它。当前人格显示「已应用」，其他人格显示「激活后应用」；保存影响后续轮次/任务，在途轮次继续使用原人格快照。业务数据/操作仍属于当前激活人格。revision 冲突时保留草稿并显示错误，可点击「重新读取」丢弃草稿后重试。迁移/profile 不可用时运行整份回退旧配置，profile 编辑被拒绝，检查迁移错误后重启重试；System/module 不受影响。

Profiles → 人格表达只有一个编辑器。人格库保留创建/复制/切换/删除/导入与数据复制；旧人格 API 编辑、reset、慢演化同步同一份 profile revision。已有 C02 未修改的快照参数会采用切换前的真实 legacy 行为，曾明确保存的 staged overrides 从本次切换开始生效；重启不会重复迁移。

命令 `/model` 同样写当前 profile。`/quiet`、`/active` 若同时改变群聊模式与主动开关，返回 SETTINGS_MULTI_OWNER 且零写入，请分别在 Profiles → 轮次与群聊参与和 Extensions → proactivity 保存。

System/数据治理设置按 owner revision 保存；凭据输入空白保留，填写新值显式 set，点击「清除」后保存才 clear。外观和内置模块旧绑定继续即时串行保存；sample/外部模块文件配置沿用模块 schema/revision。没有全量配置 reset 或第二个通用编辑器。下面按既有功能名称说明操作，位置以上表和搜索为准。

所有者设置（OwnerSettings）的「保存设置 / 重新读取」统一位于编辑器末尾、Panel 外的一组工具栏；桌面正常随内容排列，视口 ≤900px 时吸附于底部，使用不透明表面、顶部分隔线和底部安全区留白。加载失败或 revision 冲突时仍只有这一组按钮；重新读取会丢弃草稿，保存继续检查原 owner/profile revision，不会激活所编辑的人格。忙碌、无改动或 profile 编辑不可用时沿用原保存禁用条件。滚动容器为工具栏预留底部滚动空间，字段、错误提示与焦点目标保留额外滚动间距。

### 离线 Chat 沙盒（C05）

进入 **Chat & Sandbox → 离线 Sandbox**，始终确认页面的 **SIMULATION / zero real sends** 标识：

1. 点击「创建模拟」，或从「选择模拟」读取当前激活人格的已有模拟。每个模拟使用独立人格、配置、存储和固定离线回复，不复制真实聊天记录或模型凭据。
2. 选择私聊或群聊，输入文本、`/help`、`/like`、`/remind 60 离线提醒` 等命令，点击「提交模拟事件」。群聊按模拟 @ 处理；也可选择好友/入群通知或好友/加群请求。
3. 点击「推进虚拟时间」，默认 12000 毫秒，让聚合回复和计时任务运行。提醒可再推进 120000 毫秒；单次最多一天。墙钟等待不会推进模拟。
4. 查看 Transcript、Captured actions、入站与交付回执、Loop/阶段。回执的 sent/parts 只表示模拟 executor 成功，真实 QQ 发送数始终是 0。所有内容按文本展示，不加载媒体。
5. 「重置模拟」清空状态、取消未完成计时并创建新 generation；「删除模拟」移除会话目录与全部状态。两者只影响选中的模拟。

人格/配置快照仅供读取，无 live mutation；命令可能修改模拟内部状态。当前人格由服务端绑定，切到另一人格后无法访问旧模拟（not found），切回后可选择原会话。「刷新模拟」或「重新读取模拟」执行只读查询，失败时保留文本草稿，不自动重发命令。

最多 16 个活动模拟；文本最多 4000 个 UTF-16 code units，请求体最多 16 KiB；每分钟最多 120 个解析后管理请求、最多 8 个排队请求，每会话最多 1000 次 event/advance 后需重置或删除。状态只在本进程可用，重启不恢复，也无分页/导出；崩溃遗留目录需人工维护。没有真实模型/网络、媒体处理、shell 或执行沙箱。这里的合成人物不是真实 QQ 用户。API 契约和隔离限制见 [ADR-021](architecture/ADR-021-simulation-service.md)。UI 验证使用 Node React shim，未验证真实浏览器布局。

模块详情顶部为紧凑工具栏：「← 模块目录」文本链接、`模块目录 / <模块名>` 面包屑及右侧刷新图标，目标均至少 44px。h1 为模块名称，ID 使用次要小字，下方保留状态芯片、实心「配置」和次要「停用或启用」；移动主动作固定两列、44px 高，简短说明提示配置只读及启停影响。进入列表或详情时插件滚动区复位到页首并聚焦标题，异步加载完成后补焦点；刷新和健康更新不抢焦点，显式配置/功能锚点继续定位。

「模块概况」只显示说明、来源（内置受信任/外部）、版本和状态。「技术信息」默认关闭，展开后可查看并选择复制 ID、generation、uiRevision、runtimeGeneration、telemetryGeneration、observedAt、完整依赖与权限；运行代次和观测时间复用健康卡快照，不读取配置或密钥。「模块健康」显示运行正常/加载中/需要注意/已停止/错误及短说明，保留运行状态、工作阶段、健康和原因代码四项主要指标；最近错误、代次、Provider 所有者、依赖和调度/引擎/遥测计数收进默认关闭的「健康技术详情」。未知观测不算正常，历史错误不覆盖当前健康结论。

「模块操作」按「运行管理 / 手动任务」分组，每项说明影响；禁用原因通过 `aria-describedby` 关联按钮，已有操作未结束时说明等待或继续观察。已启用但 error/blocked 的模块保留「启用」恢复入口。摘要、健康、操作、功能入口、提醒数据与声明界面仍为同级区块，详情/配置/面板/提醒/字段锚点、只读预览与隔离 WebUI 都保留。移动元数据为单列条目，每条内部保持标签和值同行布局；长文本可换行、code 可选择，主要操作紧凑两列。iframe 宽度随区块缩放；数字字段与单位在移动端上下排列。

sample 与外部模块的文件配置打开后，「保存配置 / 重新加载配置 / 取消」移至详情末尾、Panel 外的唯一 `.ob-module-savebar`，采用与所有者设置相同的 ≤900px 底部吸附、安全区和滚动留白；桌面使用同一组按钮。保存仍携带 revision，成功后重读；冲突保留草稿，重新加载丢弃草稿，取消关闭编辑器与工具栏。停用或未 loaded 时配置继续只读，忙碌时按钮禁用。旧绑定的内置模块继续即时保存并显示 PreferenceSaveStatus，不显示显式保存栏。

- 统一列出内置与外部 JavaScript 模块，显示来源、两类数量、名称、版本、权限摘要及运行中/已停用/依赖受阻/加载失败状态，可手动刷新列表。

- 「模块操作」和顶部启停按服务端可用性提供启用、停用、重启、重载及主动/学习手动动作；调用前确认模型、预算或 QQ 发送影响，携带代次/人格凭证，接纳后观察到终态才报完成。STOP_PENDING 表示仍在排空；busy/skip/NO_TASK/失败不算成功。网络异常可继续观察同一操作，勿重复提交；离开页面不取消服务端操作。
- 功能入口直达 B站面板、表情包库、主动行为、学习、提醒数据或既有配置区。B站面板仅在「模块 → 媒体功能」，「内容」页直达该面板；媒体、主动行为和学习页均可返回模块详情。配置仍只有原编辑器。
- 提醒数据只显示当前人格的提醒记录数；逐条查看和取消在对应 QQ 会话使用 `/reminders`、`/forgetreminder`。
- 内置随包发布，不能重载。默认关闭的「内置示例」builtin-sample 不执行代码；启用后仅主人 `/module-sample` 返回固定一句话，没有其它默认行为。

- requires 缺失/循环令模块 error，依赖关闭或失败令下游 blocked；需要手动修复/启用依赖，不会自动开启。重载/停用先清理下游，依赖恢复后按顺序恢复符合条件的模块。

### 备份

备份页显示快照数、已保存文件大小、保留/单份大小上限与应用恢复是否开放。快照位于 `<数据目录>/backups/<id>/`，包含 `manifest.json` 与 `files/`，是**目录，不是 zip**。

1. 创建前停止认知、模块及其它所有数据写入，保证 SQLite/WAL 文件稳定；服务不会 checkpoint 或锁库，在线复制不保证数据库一致性。无法可靠停写时，请停止 DSH 后用系统工具离线复制数据根。
2. 填可选备注（最多 1000 字符），按需勾选「包含全部媒体」，点「创建备份」。默认备份配置、模型、认知、模块及表情包；不含入站/其它媒体，勾选才包含根内全部 media/。自定义根外媒体目录不会跟随复制。日志、backups、restore-*、临时文件、符号链接和特殊文件始终排除。
3. 默认最多 200 MiB、5000 文件，开启清理时保留最新 10 份。上限与清理开关可在「Data & Logs → 备份」修改；超限整次创建失败，不发布半份快照。列表可以删除不再需要的快照。
4. 恢复优先点「暂存恢复」：服务校验 manifest、路径、大小和文件 hash，复制到 `<数据目录>/restore-<id>/`，页面显示相对路径。已有同名目录会拒绝覆盖，请先移走旧暂存目录。暂存不改变当前配置/认知数据。
5. 检查暂存内容，**停止目标 DSH profile**，再把暂存目录中的文件按相对路径复制回数据根（SQLite 主库及相应 WAL/SHM 应作为同一组处理，避免遗留旧 sidecar），最后启动 DSH。恢复是覆盖备份中的文件，不会自动删除其它旧文件。

「应用恢复」默认禁用，只有 `ops.backup.allowRestore=true` 才能调用，服务端也会检查。此选项仅适合确认全部写入已停止的维护环境：先自动创建备注为 `pre-restore:<id>` 的安全快照，成功后才覆盖文件，完成后必须立即重启 DSH。途中失败可能部分覆盖，安全快照会保留；不要把正在运行的 SQLite 当作可热替换文件。日常操作建议使用暂存后停机的流程。

备份包含 `config.json`、`models.json` 中的原始密钥和 cognition 隐私，必须与数据根一样按秘密保护。备份功能无加密、zip、云端上传/下载、自动恢复或工作区迁移；版本检查在「安全」页独立提供；面板继续依赖 DSH 本机访问边界，不额外增加 API 鉴权。

### 安全与上线检查

面板现有 15 个顶层标签，其中「安全」集中展示上线状态。页面读取 `/status`、`/access/stats`、`/backup` 和 `/upgrade`；除手动版本检查外不写配置或执行操作，修改需前往「配置」。

- **访问控制**：查看 open/allowlist、主人 QQ、私聊/群白名单数量、入站/出站拦截计数及最近 5 条审计。审计仅进程内元数据，重启清空；无消息正文。
- **危险面**：查看任意 OneBot action、备份 allowRestore 开关，以及 Vision/ASR/TTS 环境变量名（不显示密钥值）。本地模块运行同一进程中的任意代码，权限门控不是沙箱。
- **出站文本防泄漏（M7-i）**：只读显示启用/禁用与 redact/block 策略，没有扫描内容/密钥；在「System → 安全」修改。
- **上线检查**：确认网关已连接、allowlist 且设置 ownerQQ、至少一份备份、raw action 关闭、媒体 provider 关闭或 URL/模型/环境变量名已填写，并人工审核模块代码与权限。列表显示通过/待检查，问题项可前往连接/配置/备份。媒体项只检查字段完整性，不读取环境变量值或探测服务；模块项始终提醒人工确认，系统不会假装完成审核。清单是 M6 的向导范围，无独立向导流程，也不保证系统已安全上线。
- **升级**：先在「Data & Logs → 备份」启用 `ops.upgrade.enabled`，再按「检查更新」。查看 current/channel/latest/updateAvailable 与检查时间、Release 链接和最多 2000 字符说明。安全页按钮使用 force=true 获取新结果；API 普通请求复用默认 60 分钟内的成功缓存。状态读取始终不联网。

检查仅访问 GitHub Releases 最近 10 条；stable 排除草稿和预发布，beta 仅放宽预发布过滤，随后按合法版本号选最大值，不改变安装或运行通道。不支持 token；未认证 API 通常每 IP 每小时 60 次，强制检查会消耗额度。失败显示 GitHub HTTP/超时/版本错误等真实原因，不伪造版本；如有旧缓存，检查时间仍为上次成功时间。

默认不联网检查，不后台轮询；无自动更新、下载或安装。操作员须自行查看 Release 并按[安装与升级说明](INSTALLATION.md)处理。本里程碑无工作区迁移、格式迁移或离峰省钱策略；安全页与现有 API 继续依赖 DSH 本机信任边界，不改变 API 鉴权，不新增 CSRF/可信反代/远端防护。

### 按所有者设置

System、Profiles 和 Data & Logs 的具体分区只渲染本目的地字段；模块字段只在 Extensions 的对应详情。旧「配置」入口直接打开 System → 常规，不再提供覆盖全部组的编辑器。保存只提交变化路径与该 owner 的 revision，冲突保留草稿并提示重新读取。

在 Profiles → 人格库管理多个人格；在 Profiles → 人格表达编辑人设并应用于后续轮次。轮次与群聊参与参数属于 Profiles → 轮次与群聊参与。

- **人格库**：保存多份互相独立的人格；下拉切换当前人格，切换后下一轮消息立即使用新人格；
- **新建人格**：填名字创建空白人格；**复制当前**：复制当前 profile/数值/风格，生成独立副本；
- **删除当前**：至少保留一份；删除当前人格会自动切到剩余人格；
- **导入人格 JSON**：接受 `persona-import@1` 格式（name/profile/traits/style/values/source），创建并激活新人格；
  适合导入外部蒸馏人格；外部包没有 LICENSE 时不要提交原文到公开仓库；
- **测试模型链路**：调用 `/cognition/llm/test` 实测当前 DSH/直连 route，显示成功 route/延迟或 provider 真实错误；
- 每份人格独立保存 profile、12 维特质、表达风格、价值边界、编辑历史与版本；旧 `self` 自动作为默认人格；
- 未保存修改时切换/新建/复制会先确认，不会静默丢草稿；
- **认知数据独立**：记忆、人物画像、关系、情绪、策略/决策、信念/学习、技能、诊断/元认知按当前人格隔离；
  切换人格等于切换整套认知状态；旧版本的无前缀数据首次启动时自动迁移到默认人格；
- **数据复制**：在「认知数据」卡片选择来源人格和数据组，把来源的指定组**单向替换**到当前人格；
  来源人格不变，复制后两者继续独立；删除人格会同时删除它的认知数据。

- **基本人设**：名字/自称、一句话介绍、身份/角色、背景；
- **性格与表达**：自然语言性格、说话风格/口癖、喜欢/不喜欢、边界/禁忌、示例对话；
- **Prompt 预览**：直接看到会注入分析与回复 system 的人设块（截断到 2000 字符）；空字段不会出现；
- **群聊参与**：
  - `仅 @ / 回复 / 唤醒词`（默认，安全）；
  - `点名必回，未点名按概率`（可调 0–1 概率）；
  - `所有群消息都分析`（仍受策略沉默、同群冷却、每分钟上限约束）；
  - 名字会作为唤醒词；群友叫 bot 名字也能触发；
- **保存**：显式保存 profile + 数值人格；有未保存改动时显示标记；
- **高级认知参数**：展开后可微调 12 维人格和 6 维表达风格；
- **演化历史**：记录人工编辑与慢演化；
- 文本人设保存在认知 SQLite 的 persona 记录，和 `config.json` 的数值初值分离；旧 persona 读取时补空 profile，不覆盖已有内容。
- 群聊仍只读本群/本作用域记忆；私聊记忆不会进入群聊 prompt。

**群聊词法相关度（M7-p，默认关闭）**：在「Profiles → 轮次与群聊参与」打开「群聊词法相关度门控」，最低分默认 0.15（范围 0–1）。未点名群消息在原有概率、分钟上限、连续上限、冷却检查通过后，复用已检索记忆的最高词法相关度；缺信号时按文本与记忆摘要的词法重合计算。无记忆或低于阈值会跳过分析/回复 LLM，但仍记忆该消息，诊断原因是 `low_relevance`。点名/回复/唤醒词绕过相关度检查，仍受分钟上限约束；私聊不受影响，关闭即保持原行为。门控不新增外部调用，计算异常放行。只做词法记忆相关度，没有 LLM 话题理解、接梗或语义打分；#20 仍 partial、remaining 47。字段和检查顺序见[配置说明](CONFIG.md#群聊词法相关度门控m7-p)。

### 模型

System → 模型管理运行中的 Provider/协议与全局额度；Profiles → 模型编辑人格模型选择与生成参数并应用于后续轮次：

- **路由模式**：在 Profiles → 模型保存后应用于当前人格后续轮次，Provider 的「设为直连/备用」操作沿用原模型服务；
- **预设**：OpenAI Chat、OpenAI Responses、Anthropic、DeepSeek、OpenRouter、OpenCode Go（OpenAI 与
  Anthropic 两种端点）、Command Code（两种）、Gemini、Ollama、Custom；
- **Provider 编辑器**：协议、base URL、请求路径、模型列表路径、认证方式、环境变量、API key、额外 headers、
  session header、模型 ID、超时、流式、重试；
- **测试**：发一个最小真实请求，显示协议/延迟/tokens/文本预览/错误；不显示 key/请求 header；
- **发现模型**：从 `/models`（或 Anthropic/Gemini/Ollama 对应端点）拉列表，确认后写入；
- **设为直连 / 设为备用**：认知默认用直连时走这里；`chain` 按 selected + fallback 顺序尝试；
- 密钥优先读环境变量（如 `OPENCODE_GO_API_KEY`）；UI 保存的 key 只在本地 `models.json`，API 只返回
  后四位和来源；留空保存表示保持原 key；
- **OpenCode Go** 必须带 `x-opencode-session`，预设已自动生成；**Command Code** 的 Go 套餐没有 API 权限
  （403），需要更高套餐；OpenRouter 聊天需要 key；
- 直连失败时按模式回退 DSH；所有路由都失败时不伪造回复，认知进入 degraded。

### Profiles 的认知数据

顶层标签「认知」是长期状态与管理界面。它不是把所有内容塞进 Prompt，而是把状态存在
`cognition/cognition.sqlite`，LLM 只做语义分析与最终表达：

| 子页 | 你看到什么 / 能做什么 |
|---|---|
| 状态 | 人物/关系/记忆/未知/决策/技能计数；当前人格摘要、模拟情绪、LLM 路由与今日预算；暂停/恢复；最近决策与未知 |
| 人格 | 12 维特质与表达风格滑杆、价值边界、演化历史；修改即时保存，可重置；单次互动不会改变长期人格 |
| 人物 | 人物列表/搜索；平台身份、分层画像（事实/自述/观察/推断/假设）、置信度/作用域；编辑单条画像（含群印象）、删除单条画像或整个人物 |
| 关系 | 10 维只读条、作用域与摘要；逐卡手动调整维度，显式保存并记录历史 |
| 记忆 | 搜索/类型过滤；情景/语义/情绪/社会/程序记忆；查看来源、重要性/访问次数；激活、遗忘（降权，不删除）、彻底删除；JSON/JSONL 旧记忆/时间轴事件导入当前人格 |
| 情绪 | 内部/外显效价、唤醒、压力、疲劳、心境与离散情绪；重置；模拟状态，不声称主观体验 |
| 策略 | 决策候选/效用/置信度/结果；标记正向/负向反馈；查看策略 Beta 后验并重置策略学习 |
| 主动行为 | 调度/引擎状态、执行一次主动行为、返回模块详情与闭环入口 |
| 闭环 | 当前人格的摘要、运行分页、阶段/交付回执、反馈来源/策略提交与研究关联详情 |
| 学习 | 未知缺口、学习任务、带引用的 knowledge claims；工具栏运行待处理，逐任务重试/取消；自动外部检索需在设置开启 |
| 技能 | 基础/有效熟练度、使用/成功/失败；压力与长期不用会降低有效值，恢复比初学更快 |
| 元认知 | 校准（Brier）、结果趋势、记忆/技能/学习健康、能力缺口与有限反思 |
| 设置（旧链接） | 只列出 profile 所有者目的地；没有第二份通用表单。模块设置直接去 Extensions，隐私/导入去 Data & Logs |

**人物与群印象编辑（M7-g）**：在「Profiles → 人物」选择当前人格的人物，点击画像项的「编辑」，修改内容（面板按 1–2000 个 Unicode 字符校验）、置信度（0–1）及可选状态 active/disputed；也可保留原状态。点击「保存」后调用既有修正接口（`actor=ui`）并刷新详情，「取消」丢弃草稿。既有接口仍按 2000 个 UTF-16 单元截断内容，含 emoji 等非 BMP 字符的长文本可能被截短。群印象就是该人物带 `group:群号` 标签的画像项；人物/facet ID 和私聊/群作用域不可编辑，不能通过此处搬移到另一作用域。单项删除和整个人物删除仍保留。

**关系调整（M7-g）**：在「认知 → 关系」核对卡片的人物和作用域，点击「调整」。滑杆使用接口返回的维度，目前为好感、熟悉、信任、亲密、尊重、戒备、冲突、舒适、主动、稳定，范围均为 -1–1。拖动只更新草稿，点击「保存」仅提交变化维度和原作用域；未修改时保存不可用。「取消」丢弃草稿；保存后刷新列表，既有后端以 `source=ui` 记录人工调整历史。只读维度条继续显示已保存值。

两处保存期间禁用编辑控件；失败显示 toast 并保留草稿供重试。操作只影响当前人格的对应记录，不批量修改、不自动应用，也不发送 QQ。尚无独立的按人物/聊天「说话方式」编辑器或 Aurabot 专用人物/群档案导入；Profiles → 人格表达页编辑的是 bot 自身风格，通用旧档案导入支持记忆与时间轴事件。

**安全默认**：

- 群聊默认只回应 @ / 回复 / 唤醒词 / 命令；`群聊非点名参与` 需显式开启；
- 主动行为默认关闭；开启后仍受安静时段、日预算、关系门槛与退避限制；
- 自动外部检索默认关闭（只检测未知）；开启后按来源、预算、许可限制，外部内容不执行指令；
- 私聊/群聊默认隔离；私聊记忆不会进入群聊检索；删除人物会级联清理其画像/关系/记忆；
- LLM 不可用/失败时进入 degraded，不伪造回复；演练模式完整决策但不发送。

「闭环」按需刷新快照，运行列表每页 50 条；从「策略」的决策可点「查看闭环」。详情展示阶段、交付状态与分段数、反馈来源/归因/观测、policy committed 与 Beta 前后值，并通过 unknown/task/evidence/claim 允许 ID 关联学习页。未观察表示没有保留观测，不适用表示该类闭环没有相应阶段，不可用表示读取失败，已中断表示执行未正常结束；均不能推断发送或学习成功。只读当前人格，不展示消息正文、QQ 标识、事件标识或任意原始记录。研究内容仍在学习页；目标任务在最近 100 条内优先显示，超出时提示当前列表未包含；每次最多展示 20 条任务。页面切换不取消服务端 operation；闭环与健康不会自动重启模块。

认知 API 前缀为 `/onebot-qq/api/cognition/*`（概览、人物、记忆、情绪、策略、学习、技能、元认知、导出/删除），
与平台配置共用同一个 DSH 认证边界。

## 5. 常见问题

### 5.1 点「连接」没反应 / 状态停在 disconnected

按顺序检查：

1. 网关是否真的在监听：`Test-NetConnection 127.0.0.1 -Port 3001`（或 `Get-NetTCPConnection -LocalPort 3001`）。
2. 地址协议是否正确：WS 必须以 `ws://` 或 `wss://` 开头，HTTP 必须 `http://`/`https://`；
   填错协议会被配置校验回退为空，并在保存结果里给出 issue。
3. 网关开的是「WebSocket 服务端（正向 WS）」还是「WebSocket 客户端（反向 WS）」？
   本插件连的是**正向 WS**；网关里的「反向 WS」需要填回调 URL，不适用于本插件。
4. 是否只填了 HTTP？只填 HTTP 时状态是 `disconnected` 且日志说明「无法实时接收事件」，
   发消息仍可用；要收事件请开正向 WS。
5. 看「日志」：`连不上 QQ 网关（…）：ECONNREFUSED` = 端口/地址不对；
   `HTTP 401` = token 不对（见 5.3）；`code 1008` / `1403` = WS 握手 token 校验失败。

### 5.2 账号核验 mismatch

`get_login_info` 返回的 QQ 号与「机器人 QQ 号」不一致。

- 改「机器人 QQ 号」为网关实际登录的号，或改成网关登录该号；
- 策略：`warn` 只告警、照常连接（推荐先用这档确认）；`enforce` 会断开 WS 并进入 `paused`，
  修好配置后需要手动点「重连」；
- `off` 完全不核验（不推荐，容易发错账号的消息）。

### 5.3 token 401 / 403 / WS 握手失败

- WS token 和 HTTP token 可能不是同一个：NapCat、SnowLuma 分别配置，逐个核对；
- 优先用默认 `bearer`（NapCat/SnowLuma 都支持）；只有网关明确不支持请求头时才用 `query`
  （token 会出现在 URL/日志里，安全性差）；
- `header-token`（`X-Access-Token`）不是 OneBot v11 标准，NapCat/SnowLuma 不读它；
- 改了 token 记得保存后点「重连」；
- 日志里的 token 会被自动替换成 `***`，这是正常的脱敏。

### 5.4 端口被占用

- 网关端口（3000/3001/8081/8083）被占用：在网关里改端口，或关掉占用进程；
  查占用：`Get-NetTCPConnection -LocalPort 3001 -State Listen | Select OwningProcess`；
- DSH Web 端口（默认 3080/6099 之外的随机端口，或你显式 `--port` 指定的）被占用：
  `dsh web --port <其它端口>`；
- DSH 插件本身不额外监听端口，REST 接口挂在 DSH Web 的 `/onebot-qq/api/*` 下。

### 5.5 已连接但收不到事件

- 确认网关推送的是 OneBot v11 事件（不是 Milky/Satori 等其它协议）；
- 看「配置 → 事件」：`events.enabled`、`events.kinds.*`、`events.messageSubTypes.*` 是否被关掉；
  `events.ignoreUsers` / `ignoreGroups` 是否把发消息的人/群过滤了；
- 刚连上的一瞬间在账号核验：核验期间事件先缓冲（上限 `verification.bufferSize`），
  核验通过后按序补发；核验失败（`enforce`）会丢弃缓冲；
- 群消息被过滤时「概览」的「已丢弃」计数与原因会增长，可据此判断。

### 5.6 SnowLuma 检测不到 / 读不到地址

- 安装目录必须是解压后的 SnowLuma 根目录（里面有 `index.mjs` 和 `config/`）；
- 路径含中文会导致 SnowLuma 无法运行（插件会提示），请用纯英文路径；
- 没有任何 `config/onebot_<uin>.json` 且全局 `onebot.json` 没开网络时读不到，属正常；
  可在 SnowLuma 里开启 OneBot 网络，或直接用手填地址模式；
- 注意 `enabled` 字段（不是 `enable`）为 `false` 的服务端不会被使用。

### 5.7 侧栏没有 bot 名称入口 / 面板空白

- 插件安装后必须**重启 DSH 进程**（网页半边在启动时加载）；
- 确认安装的 profile 就是当前启动的 profile；
- 打开 DSH Web 的带 token 地址（`?token=...`），否则页面会 401；
- 打开浏览器开发者工具 Console 看 `dsh-bot` 的 client 加载错误。

### 5.8 如何重置配置

- 面板「配置」→「恢复默认」；
- 或直接删除数据目录里的 `config.json` 后重启插件/DSH。

### 5.9 群聊/私聊不回消息（访问控制）

先看「概览 → 访问控制」卡片：

- 模式是 `open`：访问控制不是原因，按「5.5 已连接但收不到事件」和认知诊断排查；
- 模式是 `allowlist`：确认目标群/私聊在对应白名单里，且主人 QQ 填写正确；
- 看「入站拦截 / 出站拦截」计数是否增长；用 `POST /onebot-qq/api/access/check` 查询具体会话的判定与中文原因；
- 被拒消息不会出现在「消息」页，也不会写入认知库，这是预期行为。

## 6. 本地自测（没有 QQ 网关也能跑通）

仓库自带一个内存版假 OneBot v11 网关，用于人工把面板点一遍（不是真实 QQ）：

```powershell
node scripts/mock-gateway.mjs
# 可选参数：--port 6700 --token mock-token-abcdef --self-id 20000002 --nickname 测试机器人 --no-heartbeat
```

启动后会打印地址与 token（默认固定端口 `6700`）：

```
WS 地址   : ws://127.0.0.1:6700
HTTP 地址 : http://127.0.0.1:6700
token     : mock-token-abcdef
机器人 QQ : 20000002
```

在面板「连接」里填：

| 字段 | 值 |
|---|---|
| 网关类型 | 连接已有 OneBot v11 地址 |
| WebSocket 地址 | `ws://127.0.0.1:6700` |
| HTTP 地址 | `http://127.0.0.1:6700` |
| WS / HTTP access token | `mock-token-abcdef` |
| 机器人 QQ 号 | `20000002` |

保存 → 连接 → 核验应显示 `ok`、昵称「测试机器人」。

用假网关的 `_mock` 控制端点（浏览器直接打开或 `curl`/`Invoke-RestMethod`）验证面板：

```powershell
$mock = 'http://127.0.0.1:6700'

# 看连接数 / 收到多少调用 / 推了多少事件
Invoke-RestMethod "$mock/_mock/state"

# 推一条私聊消息（「消息」页事件流应出现）
Invoke-RestMethod "$mock/_mock/push" -Method Post -ContentType 'application/json' `
  -Body '{"type":"private","userId":10001,"message":"你好"}'

# 推一条群消息
Invoke-RestMethod "$mock/_mock/push" -Method Post -ContentType 'application/json' `
  -Body '{"type":"group","groupId":30001,"userId":10001,"message":"群消息"}'

# 模拟「账号不一致」：让网关返回别的 QQ 号，再点重连
Invoke-RestMethod "$mock/_mock/config" -Method Post -ContentType 'application/json' `
  -Body '{"loginUserId":"99999999"}'
# 验证完改回来
Invoke-RestMethod "$mock/_mock/config" -Method Post -ContentType 'application/json' `
  -Body '{"loginUserId":"20000002"}'

# 模拟核验慢（观察核验缓冲）
Invoke-RestMethod "$mock/_mock/config" -Method Post -ContentType 'application/json' `
  -Body '{"loginDelayMs":800}'

# 看网关收到了哪些 action（发消息后应有 send_private_msg / send_group_msg）
Invoke-RestMethod "$mock/_mock/calls"
```

验证账号不一致的两种策略：把 `botQQ` 保持 `20000002`，`loginUserId` 改成 `99999999` 后重连：
`accountCheck=warn` 应显示「账号不一致」但保持连接；`accountCheck=enforce` 应进入 `paused` 且 WS 断开。

假网关按 `Ctrl+C` 退出。它只是测试替身，不要用于真实 QQ。

## 7. 安全与隐私

M7-i 默认开启 `security.leakGuard.enabled=true`，策略 `redact` 将统一认知出站 text 段中的高置信度密钥匹配替换为 `[REDACTED]`；改为 `block` 则整条消息不发送、返回 `LEAK_BLOCKED`。扫描在访问控制和限频之后、发送之前；dry-run 也扫描，但始终不发送。阻止计入进程内 `leakBlocked`，不记为 sent；成功脱敏只返回 `leakGuard: "redacted"`。超过 100,000 个 UTF-16 单元（含一条消息的 text 段合计）时，所有文本整体脱敏或阻止；不放行未扫描的尾部。

仅识别 OpenAI/GitHub/AWS AKIA、Bearer、PEM 私钥和至少 16 字符的通用 api_key/apiKey 值，日志仅类别和次数；网关原始异常不向调用者、policy 或日志传播。安全页仅显示开关/策略，没有扫描内容/密钥。可能误报或漏报，逐段扫描不重组跨段/跨消息密钥；无 PII/熵检测、统一审批或逐项权限。非文本段不变；不扫描媒体/文件/base64，媒体独立发送路径及面板手动 `/send`、raw action 不覆盖。规则和配置见 [CONFIG 安全](CONFIG.md#38-安全security)。

- **只连回环地址**：网关建议监听 `127.0.0.1`，不要把 3000/3001/6099/5099/3080 暴露到公网。
  需要跨机访问时用 SSH 隧道或内网互信，不要 `0.0.0.0` 直连公网。
- **token 要强随机**（≥32 字符），不要复用 QQ 密码；WS/HTTP 分别设置。
- **优先 Bearer**：`query` 模式会把 token 放进 URL，容易进日志/代理记录。
- 插件侧：token 字段为 `secret` 类型；日志、错误消息、状态快照里的 token 一律替换为 `***`
  （`logging.redact` 默认开启）；状态快照只暴露脱敏后的地址。
- 事件落盘（`events.persist`）默认关闭；开启后消息内容会写到数据目录，注意磁盘与隐私。
- 原始 action 透传（`security.allowRawAction`）默认关闭，仅调试时临时打开。
- 本插件不做任何联网上报；QQ 数据只在本机 DSH 进程与你的网关之间流动。

## 8. 卸载与数据清理

```powershell
# CLI 卸载（同时移除依赖与 bundle 层）
dsh plugin --profile <profile> remove dsh-bot

# 删除插件数据（配置 / 事件落盘 / 日志）
Remove-Item -Recurse -Force "$env:USERPROFILE\.dsh\plugins-data\dsh-bot"
```

如果设置了 `DSH_BOT_DATA_DIR`，数据在它指向的目录里，等价删除即可。
卸载后重启 DSH，侧栏 bot 名称入口会消失。
